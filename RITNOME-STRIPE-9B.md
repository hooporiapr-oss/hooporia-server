# Phase 9B — review-only storage
New tables only; no DDL applied. Current licenses.id is UUID, expires_at is DATE, school_name is text. Do not derive license expiry by blindly converting Stripe timestamps to dates. Existing license_schools has a name rather than a facility UUID; registry facility_id is an internal UUID assigned by an authorized onboarding process that is not implemented yet. No anonymous access. Only server-side service_role has explicit select/insert/update grants, and RLS is enabled. Test-mode bindings cannot reference existing license records. Unique facility per mode prevents two concurrent bindings; cancellation/re-subscription requires a future audited replacement workflow; never overwrite history silently. No automatic entitlement or license creation.
The existing server database connection must not be assumed to target the licensing project. Verify server-side project configuration and use a dedicated server client if necessary. No new credentials in source. Use an isolated test project with synthetic public.licenses table first. Test duplicate events under concurrent inserts, anon/authenticated denied, service role success, mode isolation, FK and uniqueness, and error propagation; then obtain explicit migration approval. Rollback before use: drop inbox first then registry, only if both empty and explicitly approved; after use retain data and disable route. Do not mount webhook until schema, worker, reconciliation and security tests pass.
